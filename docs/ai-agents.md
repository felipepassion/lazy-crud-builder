# Using Lazy CRUD with AI coding agents

This page is written for an AI coding agent working in a solution that uses Lazy CRUD, and for the people who supervise it. It tells the agent how to classify a file before editing it, where a change belongs, what the diagnostics mean, and which machine-readable sources are authoritative.

## Read the ownership before you edit

Every file the generator writes is classified with exactly one ownership value. There are no synonyms.

| Ownership | What it means for you |
| --- | --- |
| `GeneratorOwned` | The template is the source. An edit here is protected on the next run and lost as soon as someone forces regeneration. Do not edit it. |
| `GeneratedOnce` | Scaffolded once, now user-owned. It will not be regenerated. Edit it freely. Delete it if you want a fresh scaffold. |
| `Manual` | Never written by the generator. Ordinary source, yours to edit. |

Files the generator never wrote (entity classes, `Program.cs`, project files, your own partial classes and tests) are user-owned.

## How to read the marker

Open the first lines of the file. A generated file starts with a block delimited by `<auto-generated>` and `</auto-generated>` in the comment syntax of the file type, with `key: value` lines:

```text
// <auto-generated>
// LazyCrud-Marker: v2
// Generator: Lazy.Crud.Builder
// Aggregate: Products
// Layer: Domain
// TemplateId: domain.command-handlers
// Ownership: GeneratorOwned
// GeneratorVersion: 1.2.0
// TemplateVersion: 1.2.0
// SourceTemplate: Domain/DomainCommandHandlers.tt
// Policy: Regenerated on every run. Do not edit this file: direct edits are overwritten by the next generation.
// Customize: change the template (Domain/DomainCommandHandlers.tt), the entity model, or a user-owned partial/extension file instead of this file.
// </auto-generated>
```

Rules for reading it:

- `LazyCrud-Marker: v2` identifies the format. Parse `Ownership`, `TemplateId`, `Layer`, `Aggregate`, `SourceTemplate` from the opening lines only; nothing else in the file is needed.
- `Ownership: GeneratedOnce` comes with the policy "Scaffolded once and now user-owned. This file will not be regenerated; your edits are preserved." Treat it as user code.
- A file with a `<auto-generated>` block that lacks `LazyCrud-Marker: v2` is either a legacy Lazy CRUD header (v1) or another tool's header. Do not assume it is regenerable; ask the manifest.
- No header does not mean user-owned: some file types cannot carry a comment (JSON, for example). Ask the manifest.

The manifest at `.lazycrud/manifests/{Aggregate}.manifest.json` answers the ownership of every recorded path (`files[].ownership`). A path absent from the manifest is user-owned.

## Put the change in the right place

| Change needed | Edit target |
| --- | --- |
| A field, relationship, endpoint, validation rule or display option | The entity class and its attributes under `Aggregates/{Aggregate}Agg/Entities/` in the Domain project, then regenerate. See [the model reference](model.md). |
| Behavior of a generated type | A partial class file of your own in the same project and namespace (most generated types are `partial`). |
| Behavior of a command handler, request DTO or validator | The `GeneratedOnce` seed under `Aggregates/{Agg}/CommandHandlers/`, `Aggregates/{Agg}/Requests/` or `Aggregates/{Agg}/Validators/`. |
| Something every aggregate should get | The template, in a local template fork selected explicitly (`--templates local:<dir>`, `LazyCrudTemplatesRoot`). See [Safe customization](customization.md). |
| Anything in a `GeneratorOwned` file | Not there. Editing it is lost unless the template is changed. |

After changing the model or a template, regenerate with the runner and rebuild; do not hand-edit the generated output to match.

## Drift and unverified diagnostics

Before overwriting a `GeneratorOwned` file the generator compares its content hash with the manifest and resolves one state per file. The default behavior preserves modifications.

| Diagnostic | Meaning | What to do |
| --- | --- | --- |
| `LC2001` (error, exit 7) | The file was modified outside the generator (hash mismatch). It was not overwritten; the edit is still on disk. | Find the edit (diff the file against the regenerated content), move it to the correct edit target, then rerun with `--resolution force`. If the edit must stay for now, rerun with `--resolution skip-modified`. Never delete the manifest to silence it. |
| `LC2002` (error, exit 7) | No trustworthy baseline exists for the file (after a v1 manifest migration, for example) and its content differs from the regenerated body. Nothing proves it was edited; it is protected. | Review the diff. `--resolution force` takes the regenerated content; `--resolution skip-modified` keeps the file. |
| `LC2008` (information) | An unverified file was identical to the regenerated body and was adopted as the baseline. | Nothing. |
| `LC2005` (information) | A `GeneratedOnce` file exists and was left unchanged. | Nothing; that file is user-owned. |
| `LC2006`, `LC2007` (warning) | A protected file was overwritten (force) or skipped (skip-modified) because you asked. | Confirm this was intended. |

Every affected file is reported, not only the first, and diagnostics are also written to `.lazycrud/diagnostics/{Aggregate}.diagnostics.json` so you can read them without parsing console text. See [Troubleshooting](troubleshooting.md).

## The Visual Studio prerequisite

Generation requires, in every mode including the unattended runner you invoke from a terminal or CI, an installed Visual Studio 2022 (17.x) or 2026 (18.x) on any channel (release, preview or Insiders) with the `Microsoft.VisualStudio.Component.TextTemplating` component, plus the .NET SDK 11.0, on Windows. The templates read the entity model through the Visual Studio code model, so the T4 tooling of that installation performs the transformation inside an embedded, unattended Visual Studio session. "Headless" means unattended, not Visual Studio-free.

If the runner fails with `LC4001` (exit code 3, `PrerequisiteUnavailable`):

- Report it to the user with the discovery log and the remedy from the diagnostic. The machine does not satisfy the prerequisite, or the installation needs the override `LAZYCRUD_VS_INSTANCE`.
- Do not work around it by running `dotnet build` and calling the result "generated". A plain build never transforms templates; it can succeed while producing none of the expected files, and the manifest and markers will show that nothing was generated.
- Do not remove the wrapper templates, the custom tool association or the manifest to make a build pass.

Check the machine before you promise anything:

```powershell
dotnet "$env:USERPROFILE\.nuget\packages\lazy.crud.builder.templates\1.2.0\tools\net11.0\Lazy.Crud.Builder.Platform.Tool.dll" toolchain
```

## Commands you will use

```powershell
$tool = "$env:USERPROFILE\.nuget\packages\lazy.crud.builder.templates\1.2.0\tools\net11.0\Lazy.Crud.Builder.Platform.Tool.dll"
dotnet $tool toolchain
dotnet $tool generate --solution <solution dir> --aggregate <Name> --report <file>
dotnet $tool generate --solution <solution dir> --aggregate <Name> --resolution force
dotnet $tool generate --solution <solution dir> --aggregate <Name> --resolution skip-modified
dotnet $tool hash --file <path>
dotnet $tool manifest migrate --solution <solution dir> --aggregate <Name>
```

`generate` also accepts `--templates nuget|local:<dir>`, `--no-tests`, `--skip-restore` and `--vs-instance <path>`. The report written by `--report` is JSON and records the resolved toolchain, the template source, the state of every file before the first write, every pipeline step, the manifest summary and every diagnostic.

## Authoritative machine-readable sources

Documentation prose can lag; these artifacts cannot, because the implementation produces them:

| Source | Location | Use it for |
| --- | --- | --- |
| Platform descriptor | `lazycrud/lazycrud.platform.json` inside any installed `Lazy.Crud.Builder.*` package (also `$(LazyCrudDescriptorFile)` in MSBuild after restore) | Layers, project patterns, package ids, the template registry with ids and ownership, the attribute catalog, capabilities, supported contract versions and host requirements |
| Generation manifest | `.lazycrud/manifests/{Aggregate}.manifest.json` | Ownership and content hash of every generated file, generator and contract version used |
| Diagnostics file | `.lazycrud/diagnostics/{Aggregate}.diagnostics.json` | Outcome of the last run by code, severity and path |
| Run report | The file passed to `--report` | Toolchain, template source, pre-check states, pipeline steps, manifest summary, diagnostics |
| Contract fixtures | `contracts/fixtures/v1/` in the templates package or the repository | Exact examples of every frozen contract; the fixture wins when prose and fixture disagree |

Reference pages: [Descriptor](reference/descriptor.md), [Manifest v2](reference/manifest-v2.md), [Marker v2](reference/marker-v2.md), [Ownership](reference/ownership.md), [Content hash](reference/hash.md), [Diagnostics](reference/diagnostics.md).

## Exit codes

| Code | Name | Meaning |
| --- | --- | --- |
| 0 | `Success` | The operation or every required scenario succeeded |
| 1 | `AssertionFailure` | An assertion did not hold or the operation failed |
| 2 | `UsageError` | Invalid command line or missing argument |
| 3 | `PrerequisiteUnavailable` | The Visual Studio T4 toolchain, the .NET SDK or the environment is unavailable |
| 4 | `InvalidFixtureOrSandbox` | A fixture could not be loaded or a sandbox could not be created |
| 5 | `Timeout` | A scenario or the run exceeded its timeout budget |
| 6 | `ContractMismatch` | A descriptor `contractVersion` is outside the supported range, or versions disagree |
| 7 | `OwnershipConflict` | Drifted, unverified or unknown-ownership files require an explicit resolution |
| 8 | `HarnessFailure` | The tool or the harness itself failed |

The same table is used by the harness (`pwsh scripts/e2e.ps1`, verdict line `RESULT: OK (passed=N failed=0)` or `RESULT: FAIL (...)`) and by the extension repository's CLI.

## A short checklist

1. Run `toolchain`; if it fails, report `LC4001` and stop.
2. Before editing any file, read its marker or look it up in the manifest.
3. Make the change in the model, a partial class, a seed or the template. Never in a `GeneratorOwned` file.
4. Run `generate` with the default resolution; read `.lazycrud/diagnostics/{Aggregate}.diagnostics.json`.
5. Resolve `LC2001` or `LC2002` deliberately, file by file, and say which resolution you used.
6. Build and run `dotnet test`.
