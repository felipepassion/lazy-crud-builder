# Marker header v2

Every file the generator writes with ownership `GeneratorOwned` or `GeneratedOnce` begins with a marker header, provided its file type has a safe comment syntax. The marker is a frozen shared contract (contractVersion 1): it is emitted by the shared writer (never hand-written by templates), parsed by every consuming surface, and excluded from the content hash.

- Fixtures: `contracts/fixtures/v1/markers/GeneratorOwned.<ext>.txt` and `GeneratedOnce.<ext>.txt` for `cs`, `css`, `razor`, `tt`, `bat`, `sql`, `ps1`, `md`
- When prose and fixture disagree, the fixture wins.

## Format

The block is a sequence of comment lines: the opening tag `<auto-generated>`, one `Key: value` line per field, and the closing tag `</auto-generated>`. Line comments prefix every line; block comments add a bare opener line before and a bare closer line after. Lines end with CRLF as written; readers must accept LF.

| Line | Value | Presence |
| --- | --- | --- |
| `<auto-generated>` | opening tag (recognized by .NET tooling and analyzers) | always |
| `LazyCrud-Marker: v2` | format version | always |
| `Generator: Lazy.Crud.Builder` | generator identity | always |
| `Aggregate: <name>` | aggregate name | always |
| `Layer: <id>` | layer id, for example `Domain`, `Tests.Domain`, `WebApi` | always |
| `TemplateId: <id>` | stable template id from the descriptor registry | always |
| `Ownership: GeneratorOwned` or `Ownership: GeneratedOnce` | ownership | always; `Manual` files are never marked |
| `GeneratorVersion: <version>` | platform version (`1.1.0`) | always |
| `TemplateVersion: <version>` | template version | when the descriptor supplies one (always at 1.1.0) |
| `SourceTemplate: <path>` | template source file named in the customization directive, for example `Domain/Filters.tt` | when known |
| `Policy: <text>` | the editing policy for the ownership | always |
| `Customize: <text>` | where to make changes instead | always |
| `</auto-generated>` | closing tag | always |

Policies (exact text):

- `GeneratorOwned`: `Regenerated on every run. Do not edit this file: direct edits are overwritten by the next generation.` followed by `Customize: change the template (<SourceTemplate>), the entity model, or a user-owned partial/extension file instead of this file.` (`the template` alone when no source template is known).
- `GeneratedOnce`: `Scaffolded once and now user-owned. This file will not be regenerated; your edits are preserved.` followed by `Customize: edit this file freely; delete it if you want the generator to scaffold it again.`

The `GeneratedOnce` header deliberately does not contain the "overwritten" wording, so a person or an agent never mistakes a user-owned seed for regenerable output.

## Comment syntaxes

| Syntax id | Opener | Line prefix | Closer | File types |
| --- | --- | --- | --- | --- |
| `line-slash` | | `// ` | | `.cs`, `.ts`, `.js`, `.java`, `.kt`, `.go`, `.swift`, `.rs`, `.c`, `.cpp`, `.h`, `.hpp`, `.scala`, `.dart` |
| `block-c` | `/*` | ` * ` | ` */` | `.css`, `.scss`, `.less`, `.sass`, `.razor.css`, `.cshtml.css` |
| `block-razor` | `@*` | ` ` | `*@` | `.razor`, `.cshtml` |
| `block-t4` | `<#/*` | ` ` | `*/#>` | `.tt`, `.ttinclude` |
| `line-rem` | | `REM ` | | `.bat`, `.cmd` |
| `line-dash` | | `-- ` | | `.sql` |
| `line-hash` | | `# ` | | `.ps1`, `.psm1`, `.psd1`, `.sh`, `.py`, `.rb`, `.yml`, `.yaml`, `.toml` |
| `block-html` | `<!--` | ` ` | `-->` | `.md`, `.html`, `.htm` |

Any other extension (for example `.json`, `.xml`, `.csproj`) has no safe comment syntax: the file is written without a marker, still recorded in the manifest with its ownership, and hashed as a whole body (`hashScope` `body-lf`).

## Parsing rules

A reader locates the block from the opening lines only, without reading the rest of the file:

1. Skip a leading UTF-8 byte-order mark.
2. The `<auto-generated>` tag must be on line 1, or on line 2 when line 1 is a bare comment opener (`/*`, `@*`, `<#/*`, `<!--`, `/**`). Comment decorations (`//`, `///`, `/*`, `@*`, `<#/*`, `<!--`, `REM `, `::`, `--`, `#`, `*`, `'` and the matching closers) are stripped before comparison.
3. The `</auto-generated>` tag must follow within 80 lines. A bare closer on the next line (`*/`, `*@`, `*/#>`, `-->`, `**/`) belongs to the block.
4. The body starts after the newline that terminates the last block line.
5. Every `Key: value` line inside the block is collected (first occurrence wins, keys case-insensitive).
6. A block containing `LazyCrud-Marker: v2` is a v2 marker; `Generator`, `Aggregate`, `Layer`, `TemplateId`, `Ownership` and `GeneratorVersion` must be present and `Ownership` must parse, otherwise the marker has problems (reported as `LC2009` when the body still matches the manifest).
7. A block without that key that mentions `LazyCrud`, `Lazy CRUD` or `T4 template` is a historical v1 header; any other `<auto-generated>` block is foreign (another tool's).

The block boundary rule is also published in `contracts/fixtures/v1/hash-vectors.json` as `markerBlockRule`.

## Relation to the content hash and to drift

The marker block is removed before hashing (`hashScope` `body-lf-marker-excluded`), so two files with identical bodies and different headers (for example different `GeneratorVersion` values) hash identically, and a marker-format change never registers as drift. A missing or malformed marker on a body that matches the recorded hash is a marker problem (`LC2009`, warning) and the file is regenerated with a valid header; it is not drift. See [Content hash](hash.md).

A v1 header is recognized for detection only: a file carrying it is identified as generated (`LC2011`) but is never overwritten on that basis alone; it is `unverified` until proven identical or resolved explicitly, and is rewritten with a v2 header once verified.

## Switching the capability off

`GeneratedCodeMarkers` set to `False` in `lazy.settings` disables emission (`LC5004`); files are then hashed as a whole body. The default is on, and the descriptor lists `generated-code-markers` among the capabilities of the build.
