## Why

Lazy CRUD is being relaunched publicly as a **domain-to-architecture compiler**, not a scaffolder: the declarative entity/property/attribute model is the input, the per-layer templates are the compiler, `Lazy.Crud.Builder.*` + `Lazy.Crud.CrossCutting.*` are the runtime/standard library, and generated code is a regenerable artifact. The Builder repository owns the framework, packages, templates, metadata and contracts that every surface (VSIX extension, CLI, AI agents) consumes — but today those contracts are implicit, drifted, and unverified end to end.

Concretely, the current state blocks a credible public launch:

- **No canonical source of truth.** Platform version, supported layers, PackageId per layer, template location/version and capabilities are re-derived (and disagree) across `Directory.Build.props`, 16 `.csproj` files, `pack-all.ps1` and the client tools. The clients default `TemplatesNuGetPackageId` to `Lazy.Crud.Templates` (`LazyCrud.Core/Models/SettingsModel.cs:95`) while the Builder ships `Lazy.Crud.Builder.Templates` — a package that `pack-all.ps1` never packs and that exists in no NuGet cache.
- **Generated code has no ownership contract.** `SaveOutput`/`SaveOutputToSubFolder` in `src/ProjectFiles/project.tt` encode ownership only as a `recreateFileIfExists` boolean (60 call sites: 43 declare overwrite, 5 declare write-once, and 12 rely on the default). Only the test templates emit an `<auto-generated>` header, so the other 89 non-test templates emit files that neither a human nor an AI agent can classify before editing.
- **Human/AI edits are silently destroyed.** Nothing compares on-disk content against the last generated hash before overwriting, and `SaveOutputToSubFolder` wraps the entire write in an empty `catch (Exception ex) { }` (`src/ProjectFiles/project.tt:1652`), so a failed write is indistinguishable from a successful one.
- **The generation manifest is not a usable contract.** `.lazycrud/manifests/Products.manifest.json` publishes absolute paths from another machine (`E:\repos\...`), `TemplateName: "Unknown"`, an empty `ContentHash`, and a hardcoded `GeneratorVersion: "1.0"` — with no ownership, no template version, and no drift-detection data.
- **The public artifact is never validated as a public artifact.** Client template resolution falls back to local source whenever the NuGet package is missing (`TemplateSourceResolver.ResolveNuGet` calls `ResolveLocal` on every miss), so a broken public distribution is masked on developer machines. There is no CI (`.github/workflows/` is empty) and no end-to-end proof.

Existing consumers make compatibility non-negotiable: Tio-Sam pins **mixed versions** (`1.0.32` for most packages, `1.0.29` for three) and declares `Lazy.Crud.Builder.Templates` `1.0.1`, while shipping its own fork of the templates project — evidence that package-only consumption does not yet work.

The extension repository is planning the consuming half in parallel (`launch-lazy-crud-public-platform`). Two teams applying against contracts that are merely described in two places is how the current `Lazy.Crud.Templates` mismatch happened. So this change **freezes the shared contracts with the Builder as the canonical authority** — descriptor, manifest v2, hash semantics, ownership vocabulary, marker v2 and the shared exit-code table — and publishes fixtures generated by the implementation so the consuming side tests against the authority rather than a hand-copied schema. Freezing is the whole point of this revision: both repositories can then apply independently without drifting.

## What Changes

- **Publish the canonical machine-readable contract** `lazycrud.platform.json`, generated from the build, embedded in every package, validated in CI, and consumed by every surface instead of hardcoded strings. It carries `schemaVersion`, `contractVersion`, `platformVersion`; `layers[]` with package id, project pattern, per-layer template package and in-package path; a `templates` registry of template ids with source file, output pattern, ownership and version; the `attributes[]` catalog identity the extension needs; `capabilities[]`; and `compatibility`. The Builder is the canonical authority: no consumer may depend on a field the Builder does not promise here.
- **Formalize generated-code ownership** as an explicit three-value contract — `GeneratorOwned` (regenerated every run), `GeneratedOnce` (seeded once, then user-owned), `Manual` (never touched) — declared per template rather than inferred from a boolean.
- **Emit a universal marker header on every generated file**, readable by humans, tools and AI coding agents, with a *distinct* message for `GeneratedOnce` files so agents do not treat a user-owned seed as regenerable. Generalize the `<auto-generated>` convention already used by `Tests.Common.ttinclude` into uniform policy.
- **Freeze generation manifest v2**: `schemaVersion`, `aggregateName`, `generatedAtUtc`, `generatorVersion`, `contractVersion`, and per file `relativePath` (forward slashes), `layer`, `templateId`, `templateVersion`, `ownership`, `contentHash`, `hashAlgorithm`, `hashScope`. Paths are never absolute. v1 manifests are migrated, never hard-failed, and migration never invents missing data.
- **Freeze hash semantics**: SHA-256 over the file body with line endings normalized to LF, excluding the Lazy CRUD marker block, recorded as `hashAlgorithm` and `hashScope`. Generation, drift detection, the E2E harness and every consuming tool use this identical rule; the marker is validated separately.
- **Add drift protection before overwrite**: a `GeneratorOwned` file is `verified`, `drifted`, `unverified` or `missing` before anything is written. A drifted or unverified file is never overwritten by default, and an absent baseline never authorizes a destructive write — an unverified file whose regenerated body is byte-identical adopts its baseline silently, and one that differs is protected with a diagnostic distinct from drift.
- **Remove silent failures from the generation path**, starting with the empty catch around the file write, and make every diagnostic testable.
- **Extract output, ownership, manifest and diagnostics from T4 into testable code** incrementally, preserving accumulated T4 behavior instead of rewriting the generator. The extraction itself is byte-compatible for existing aggregates, verified by a golden-output test. The one intentional byte change is the marker header (below), which ships behind a capability flag; every other semantic change is opt-in.
- **Treat attribute XML documentation as a public product contract.** `summary`, `category`, `param` and `remarks` already ship in the `.xml` doc file (42 `<category>` entries) and drive extension UX; normalize them, close gaps (`SubMenuSection` has none), and fix `MenuSection`/`SubMenuSection`, which are documented as attributes but do not derive from `Attribute`.
- **Consolidate versioning, packaging and publication** into one policy: a single version source, the templates package identity conflict resolved with a compatibility shim, and per-layer `contentFiles` collisions eliminated. **BREAKING** for the undocumented `contentFiles/any/any/T4/` glob in `Directory.Build.props` — dead configuration that no shipped package uses and that would silently double-pack templates.
- **Rewrite the public Builder documentation as product documentation**: README, quickstart, architecture, aggregates/entities/attributes, generated-code policy, safe customization, migrations, testing, compatibility matrix, troubleshooting, release guidance, and a dedicated "Using Lazy CRUD with AI coding agents" section. Fix the current .NET/version/naming drift (README claims ".NET Core 8.0"; packages target `net10.0`).
- **Add a clean-room public-distribution phase** that validates the package exactly as an external user receives it, with local-source and private-feed fallbacks disabled so a broken distribution fails loudly. Clean room means no private source and no non-public feed — **not** a bare machine: the validating host satisfies the declared platform prerequisites, including the installed Visual Studio toolchain, because that is what a real external user is required to have.
- **Declare Visual Studio an official platform prerequisite** for T4 generation in every mode, including headless and CLI, and transform through the T4 tooling that installation provides — as the product has always done. **Headless means unattended**, not Visual Studio-free: no prompts, no window to drive, no person clicking. The toolchain is resolved deterministically through the Visual Studio Installer query tool (`vswhere`) or the Setup Configuration API, including prerelease and Insiders channels, never by hardcoded paths or recursive directory scans, and the resolved instance is reported in every run. When it cannot be resolved, the CLI and harness fail before transforming anything, with an actionable diagnostic and the prerequisite-unavailable exit code — never a `dotnet build` standing in for generation. Today the ecosystem's headless path runs `dotnet build` while the only generator association is the Visual Studio custom tool `TextTemplatingFileGenerator`, so it can transform nothing and still exit zero.
- **Publish versioned cross-repository contract fixtures** — descriptor, manifest v2, v1-to-v2 migration pair, marker examples, hash vectors, and JSON Schemas — generated by the implementation itself, so the extension repository tests against the authority instead of reproducing schemas by hand. The fixture wins when prose and artifact disagree.
- **Add a single-command E2E harness** that builds a temporary sandbox, consumes only public-equivalent artifacts, creates an aggregate, generates layers, validates markers/manifests/hashes/ownership, compiles and tests, simulates an external edit to a generated file, and proves the protection and diagnostics fire — with reliable exit codes and machine-readable artifacts.
- **Remove the committed NuGet API key from the repository** and read publish credentials from the environment, with a CI credential scan. `pack-all.ps1` carries a live publish key as a default parameter value, committed at `HEAD` (`d8bb986`) in a public repository, with a second distinct key in the working tree. Rotating the leaked keys themselves is an **external prerequisite** for the account holder, tracked in the design and deliberately outside the implementable task list.

## Capabilities

### New Capabilities

- `platform-descriptor`: the canonical machine-readable contract — `schemaVersion`/`contractVersion`/`platformVersion`, layers with per-layer template packages, the template registry with ids and ownership, the attribute catalog, capabilities and compatibility — consumed by all surfaces.
- `generated-code-ownership`: the `GeneratorOwned` / `GeneratedOnce` / `Manual` ownership model and its per-template declaration.
- `generated-code-markers`: the frozen marker v2 header — generator, aggregate, layer, `templateId`, ownership and versions — with distinct human/AI directives per ownership, excluded from the content hash.
- `generation-manifest-v2`: the frozen manifest contract — relative forward-slash paths, `templateId`, versions, `contractVersion`, ownership, `contentHash` with declared algorithm and scope — plus v1 migration that never invents data.
- `drift-protection`: the `verified`/`drifted`/`unverified`/`missing` states, the frozen hash comparison behind them, and the explicit resolutions — including the rule that an absent baseline never authorizes a destructive overwrite.
- `generation-diagnostics`: elimination of silent failures and the actionable, testable diagnostic contract for the generation pipeline.
- `attribute-metadata-contract`: exactly what the Builder publishes for consumer attribute UX — catalog identity and structure in the descriptor, prose (`summary`/`param`/`remarks`) in the shipped XML documentation, joined by `documentationId` — so no consumer keeps its own taxonomy.
- `package-distribution`: versioning, packaging, template package identity, `contentFiles` layout, compatibility matrix and publication policy.
- `clean-room-validation`: validation of the published artifact exactly as an external consumer receives it, with local and private fallbacks disabled.
- `builder-documentation`: the public product documentation set, including the AI-coding-agents guide.
- `e2e-verification-harness`: the single-command, unattended, reproducible E2E battery with positive, compatibility-regression, toolchain-prerequisite and intentional-failure scenarios, using the frozen semantics and published fixtures.
- `t4-toolchain-prerequisite`: Visual Studio as a declared, deterministically discoverable prerequisite for T4 generation; the definition of headless; early failure with an actionable diagnostic; and preservation of the existing pipeline gates.
- `contract-fixtures`: the versioned, implementation-generated fixtures and JSON Schemas for every frozen shared contract, consumable by the extension repository.

### Modified Capabilities

None. `openspec/specs/` contains no published capability specs, so every capability above is introduced new by this change.

## Impact

**Code**
- `src/ProjectFiles/project.tt` — output, ownership, diagnostics (`SaveOutput`, `SaveOutputToSubFolder`, `GetGenerationOutputPath`); the highest-risk file, changed incrementally.
- `src/ProjectFiles/**/*.tt` (98 template files) and `src/ProjectFiles/Tests/Tests.Common.ttinclude` — marker headers and ownership declarations.
- `src/Builder/Builder.Application.DTO/Attributes/*.cs` (43 files) — XML documentation normalization and the two non-`Attribute` types.
- New testable library for output/ownership/manifest/diagnostics, plus unit tests; `src/Test/*` (8 test projects, only 3 with a `.csproj`) preserved and extended.

**Packaging and distribution**
- `Directory.Build.props`, `Directory.Build.targets`, 16 `.csproj` files, `pack-all.ps1`, `pack-infra.ps1` (currently points at the non-existent `src/Core/Core.Infra.IoC`), `publish-all.ps1`, `scripts/`, `build/`.
- `src/Templates/LazyCrud.Templates/` — the `PackageId` conflict, and `build/LazyCrud.Templates.targets`, which NuGet never auto-imports because its filename does not match the `PackageId`.
- New `.github/workflows/` CI (none exists today).

**Contracts consumed downstream**
- `.lazycrud/manifests/*.manifest.json` and `.lazycrud/cache/*.cache.json`, read by `LazyCrud.Core/Services/GenerationManifestCore.cs` and the VSIX. Manifest v2 is additive; v1 stays readable.
- `lazy.settings` keys (`TemplatesNuGetPackageId`, `GenerationOutputPath`, layer patterns) used by Tio-Sam and other solutions.

**Consumers**
- CopilotSpeaker, Tio-Sam and Nutri.Veda. Tio-Sam's mixed version pins and forked templates project define the compatibility baseline the E2E regression scenarios must protect. Nutri.Veda's coupling is unverified and is an external prerequisite before the compatibility matrix claims to cover it.

**Cross-repository**
- The extension's `launch-lazy-crud-public-platform` consumes every frozen contract here. Three points where this freeze changes what that OpenSpec currently specifies, and which its side must adopt: the content hash **excludes the marker block**; a missing hash or ownership after v1 migration produces an `unverified` file that is protected rather than a `GeneratorOwned` file that may be overwritten; and its `headless` harness tier is redefined as *unattended on a machine meeting the prerequisite*, rather than "a machine with no Visual Studio installed". Its `headless` versus `ide` tier split remains valid — the `ide` tier drives a real window, the headless tier only invokes the installed tooling.
- The published fixtures are the tie-breaker when prose and artifact disagree.

**Security**
- Two NuGet publish credentials are exposed; one is committed to a public repository. Removing them from the repository and moving to environment credentials is implementable here; rotating them is an external prerequisite for the account holder.

**Out of scope**
- The `LazyCrudExtension` VSIX/CLI implementation. This change defines the contracts the extension consumes and validates them from the Builder side; the extension's adoption is a separate change in that repository.
